ChatGPT 같은 언어 모델은 한 번의 학습으로 완성되지 않는다. 먼저 방대한 텍스트에서 언어와 지식의 패턴을 배우고, 그다음 사람의 지시를 따르며 유용하고 안전하게 답하도록 행동을 조정한다.

```text
Pretraining → SFT → Preference optimization → Optional task adaptation
    능력        지시 수행       선호 정렬              특정 업무 적응
```

이 글에서는 이 과정을 다음 토큰 예측부터 RLHF와 DPO, LoRA와 QLoRA까지 하나의 흐름으로 연결한다. 마지막에는 에이전틱 코딩 프로젝트에서 Fine-tuning과 RAG 중 무엇을 먼저 선택해야 하는지도 정리한다.

## 1. 다음 토큰 예측이 어떻게 능력이 되는가

Pretraining의 기본 목표는 단순하다. 앞에 나온 토큰을 바탕으로 다음 토큰의 확률분포를 예측한다.

> 오늘 날씨가 너무 더워서 에어컨을 **___**.

모델이 다음과 같은 확률을 냈다고 하자.

| 후보 | 확률 |
| --- | ---: |
| 켰다 | 0.550 |
| 샀다 | 0.120 |
| 공부했다 | 0.003 |
| 먹었다 | 0.001 |

`켰다`에 높은 확률을 주려면 모델은 단어 순서만 외워서는 부족하다. 날씨와 더위의 관계, 에어컨의 용도, 문장의 문법과 문맥을 함께 반영해야 한다. 수많은 문장에서 다음 토큰을 반복해서 예측하는 동안 이런 통계적·의미적 관계가 파라미터에 압축된다.

학습 목표는 전체 시퀀스에서 정답 토큰의 음의 로그 확률을 줄이는 것이다.

$$
\mathcal{L}(\theta)=-\sum_{t=1}^{T}\log p_\theta(x_t \mid x_{<t})
$$

정답이 `우산`인데 모델이 0.1의 확률만 줬다면 해당 위치의 손실은 $-\log(0.1)$로 커진다. 역전파는 각 파라미터를 조금 바꿨을 때 손실이 얼마나 변하는지, 즉 기울기를 계산한다. 경사하강법은 그 반대 방향으로 파라미터를 업데이트한다.

$$
\theta \leftarrow \theta-\eta\nabla_\theta\mathcal{L}
$$

여기서 $\eta$는 학습률이다. 이 과정을 요약하면 다음과 같다.

```text
토큰 입력 → 확률 계산 → 손실 계산 → 역전파 → 파라미터 업데이트
```

다만 이것이 모델 안에 명시적인 논리 규칙이나 사실 데이터베이스가 생긴다는 뜻은 아니다. 모델은 학습 데이터의 패턴을 분산된 수치 표현으로 학습한다. 그래서 익숙한 관계를 새로운 문장에 일반화할 수 있지만, 그럴듯하면서 틀린 답도 만들 수 있다.

### 왜 미니배치를 사용하는가

한 문장의 기울기만 따라가면 업데이트 방향이 특정 표현에 과도하게 좌우될 수 있다. 실제 학습에서는 여러 시퀀스의 기울기를 모아 평균 또는 합을 구한 뒤 한 번 업데이트한다.

```text
문장 1의 gradient ┐
문장 2의 gradient ├─ 집계 → parameter update
문장 3의 gradient ┘
```

미니배치는 업데이트의 분산을 줄이고 GPU 병렬 연산을 활용하기 좋다. 배치가 크다고 항상 좋은 것은 아니다. 메모리, 처리량, 최적화 안정성, 일반화 성능 사이에서 적절한 크기를 찾아야 한다.

## 2. Scaling Laws: 무엇을 얼마나 늘려야 하는가

언어 모델의 성능은 대체로 세 가지 자원과 함께 좋아진다.

1. 모델의 파라미터 수
2. 학습 데이터의 양과 품질
3. 학습에 사용하는 연산량

파라미터는 패턴을 표현할 수 있는 용량을 제공한다. 데이터는 모델이 접하는 지식과 관계의 범위를 넓힌다. 연산량은 그 모델과 데이터를 실제로 충분히 학습하는 데 필요하다.

Scaling Laws의 중요한 메시지는 무조건 모델만 크게 만들라는 것이 아니다. 일정 범위에서 자원을 늘리면 손실이 비교적 예측 가능한 형태로 감소하지만, **고정된 연산 예산에서는 모델 크기와 학습 토큰 수의 균형**이 중요하다. 큰 모델을 너무 적은 데이터로 학습하면 연산 예산을 효율적으로 쓰지 못할 수 있다.

## 3. Pretraining만으로는 왜 ChatGPT가 되지 않는가

Pretraining의 목표는 사용자의 의도를 파악해 친절하게 답하는 것이 아니라, 주어진 텍스트의 다음 토큰을 잘 예측하는 것이다. 따라서 기본 모델은 문서를 이어 쓰거나 여러 형식의 텍스트를 생성할 수 있어도, 지시를 일관되게 따르는 대화형 도우미처럼 행동한다는 보장이 없다.

> Pretraining은 모델에 **무엇을 말할 수 있는지**를 넓게 학습시키고, Post-training은 그 능력을 **어떻게 꺼내 쓰고 행동할지** 조정한다.

이 구분은 직관을 위한 표현이다. 두 단계가 완전히 분리된 것은 아니다. SFT에서도 새로운 지식이나 작업 패턴을 배울 수 있고, Pretraining 데이터의 구성 역시 모델의 행동에 영향을 준다.

## 4. SFT: 지시와 좋은 답변을 모방하기

SFT(Supervised Fine-Tuning)는 보통 다음과 같은 고품질 예시를 사용한다.

```text
사용자 지시 → 의도에 맞는 모범 답변
```

학습 방식 자체는 여전히 정답 답변의 다음 토큰을 예측하는 지도학습이다. 가장 큰 차이는 데이터의 성격과 목적이다.

| 구분 | Pretraining | SFT |
| --- | --- | --- |
| 데이터 | 웹 문서, 책, 코드 등 대규모 코퍼스 | 지시와 모범 답변의 고품질 쌍 |
| 주된 목표 | 일반적인 언어·지식 패턴 학습 | 지시 수행과 답변 행동 학습 |
| 규모 | 매우 큼 | 상대적으로 작고 선별됨 |
| 결과 | Base model | Instruction-tuned model |

SFT는 이미 학습한 능력을 대화와 지시 수행 형태로 끌어내는 데 효과적이다. 그러나 하나의 모범 답변을 정답처럼 모방하는 것만으로는 여러 답변의 상대적인 품질을 충분히 표현하기 어렵다. 그래서 사람이나 평가 모델이 어느 답변을 더 선호하는지 이용하는 단계가 이어진다.

## 5. RLHF와 DPO는 무엇을 최적화하는가

같은 질문에 대해 두 답변을 만든 뒤 사람이 더 나은 답변을 선택했다고 하자.

```text
x          : 사용자 질문
y_chosen   : 선호한 답변
y_rejected : 덜 선호한 답변
```

이 비교는 정답 문장 하나보다 풍부한 신호를 준다. 모델이 어떤 답변을 더 정확하고 유용하며 안전한 것으로 취급해야 하는지 알려주기 때문이다.

### RLHF

고전적인 RLHF(Reinforcement Learning from Human Feedback) 파이프라인은 먼저 선호 비교 데이터로 보상 모델을 학습한다. 이후 언어 모델이 높은 보상을 받는 답변을 만들도록 강화학습으로 최적화한다.

```text
인간의 답변 비교 → 보상 모델 학습 → 답변에 점수 부여 → 정책 모델 최적화
```

보상 모델의 허점을 공략하는 방향으로 정책이 움직이는 `reward hacking`이 생길 수 있고, 강화학습 단계의 튜닝도 복잡하다. 그래서 보통 KL 제약 등을 사용해 정책이 기준 모델에서 지나치게 멀어지지 않도록 한다.

### DPO

DPO(Direct Preference Optimization)는 별도의 보상 모델과 온라인 강화학습 단계를 두지 않고, 선호한 답변의 상대적 확률은 높이고 비선호 답변의 상대적 확률은 낮추도록 언어 모델을 직접 학습한다.

```text
선호 비교 데이터 → 언어 모델 직접 업데이트
```

DPO는 파이프라인을 단순화하고 대체로 구현하기 쉽지만, RLHF의 모든 문제를 자동으로 해결하는 방법은 아니다. 결과는 여전히 선호 데이터의 품질과 분포, 기준 모델, 하이퍼파라미터에 크게 의존한다.

| 항목 | RLHF | DPO |
| --- | --- | --- |
| 보상 모델 | 별도로 학습 | 별도 모델 없음 |
| 강화학습 단계 | 필요 | 불필요 |
| 학습 복잡도 | 높음 | 비교적 낮음 |
| 제어 방식 | 보상 설계를 통해 유연하게 조정 | 선호 데이터에 직접 의존 |
| 주요 위험 | 학습 불안정성, reward hacking | 데이터 편향, 분포 밖 일반화 |

## 6. Full Fine-tuning, LoRA, QLoRA

특정 도메인이나 출력 형식에 맞게 모델을 조정할 때 모든 파라미터를 다시 학습할 필요는 없다.

### Full Fine-tuning

Full Fine-tuning은 모델의 모든 가중치를 업데이트한다. 표현을 크게 바꿀 수 있지만 각 파라미터의 gradient와 optimizer state, 중간 activation까지 관리해야 하므로 GPU 메모리와 연산 비용이 크다. 충분한 데이터와 인프라가 있고 모델의 행동을 폭넓게 바꿔야 할 때 적합하다.

### LoRA

LoRA(Low-Rank Adaptation)는 기존 가중치 $W$를 동결하고 작은 저랭크 행렬 $A$, $B$만 학습한다.

$$
W' = W + \Delta W, \qquad \Delta W = BA
$$

$W$가 $4096 \times 4096$이고 rank $r=8$이라면 전체 행렬을 직접 업데이트하는 대신 $4096 \times 8$과 $8 \times 4096$ 크기의 행렬을 학습한다. 학습 파라미터와 optimizer state가 크게 줄어드는 이유다.

저랭크라는 제약 때문에 변화의 폭이 제한될 수 있다. 이때 rank를 높이거나 더 많은 레이어에 어댑터를 적용할 수 있지만 비용도 함께 증가한다.

### QLoRA

QLoRA는 동결된 기본 모델 가중치를 주로 4비트로 양자화해 저장하고, 그 위의 LoRA 어댑터를 학습한다. LoRA가 **학습할 파라미터 수**를 줄인다면 QLoRA는 여기에 **기본 모델이 차지하는 메모리**까지 줄인다.

| 방식 | 업데이트 범위 | 메모리 비용 | 적합한 상황 |
| --- | --- | --- | --- |
| Full Fine-tuning | 전체 가중치 | 매우 큼 | 충분한 자원으로 큰 행동 변화를 학습할 때 |
| LoRA | 저랭크 어댑터 | 낮음 | 형식·말투·도메인 작업을 효율적으로 조정할 때 |
| QLoRA | 양자화된 모델 + 저랭크 어댑터 | 더 낮음 | 제한된 GPU 메모리로 큰 모델을 조정할 때 |

양자화는 정밀도 손실 가능성이 있고, QLoRA가 언제나 LoRA보다 빠르거나 최종 품질이 높다는 뜻도 아니다. 하드웨어의 양자화 연산 지원과 실제 평가 결과를 함께 봐야 한다.

## 7. Fine-tuning과 RAG 중 무엇을 선택해야 하는가

Fine-tuning과 RAG는 해결하는 문제가 다르다.

- **Fine-tuning**은 파라미터를 바꿔 모델의 행동 방식, 형식, 말투, 반복 작업 패턴을 학습한다.
- **RAG**는 요청 시점에 관련 문서를 검색해 컨텍스트에 넣고, 최신 외부 지식을 근거로 답하게 한다.

회사 규정과 내부 문서처럼 계속 바뀌는 지식은 대체로 RAG에 더 적합하다. 문서가 바뀌면 검색 인덱스를 갱신하면 되지만, Fine-tuning으로 사실을 주입하면 변경될 때마다 다시 학습해야 하고 출처 추적도 어렵다.

반대로 출력 JSON 스키마, 특정 코드 리뷰 형식, 반복되는 도메인별 응답 습관처럼 **행동을 일관되게 바꾸는 문제**에는 Fine-tuning이 도움이 될 수 있다.

## 8. 에이전틱 코딩 프로젝트의 현실적인 선택 순서

에이전틱 코딩 시스템을 만든다고 처음부터 Fine-tuning할 필요는 없다. 나는 다음 순서가 현실적이라고 본다.

1. 먼저 강한 기본 모델과 명확한 프롬프트로 기준 성능을 만든다.
2. 저장소 탐색, 테스트 실행, 문서 검색 같은 도구와 RAG를 연결한다.
3. 실제 실패 사례를 모아 재현 가능한 평가 세트를 만든다.
4. 반복적이고 안정적인 행동 문제가 확인될 때 SFT나 LoRA를 검토한다.
5. 사람의 선호를 반영해야 하고 충분한 비교 데이터가 있을 때 DPO나 RLHF를 고려한다.

모델이 저장소의 최신 코드를 모르는 문제는 RAG와 도구 연결의 문제에 가깝다. 반면 항상 같은 형식의 패치를 만들지 못하거나 조직의 리뷰 규칙을 반복해서 어기는 문제는 Fine-tuning 후보가 될 수 있다.

결론은 간단하다. **Pretraining은 모델의 가능성을 넓히고, Post-training은 그 가능성이 사람에게 유용한 행동으로 나타나도록 방향을 잡는다.** 그리고 실제 제품에서는 학습 기법보다 먼저, 해결하려는 문제가 지식의 부족인지 행동의 불일치인지 구분해야 한다.
